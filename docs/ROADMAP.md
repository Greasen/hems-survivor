# HEMS Survivor 开发路线图

项目拆分为 7 个阶段。每个阶段都应该有可验证的完成目标，不在前一阶段尚未验证时过早扩张范围。

## 阶段 1：游戏策划

### 工作内容

- 确定一局游戏的核心规则、资源关系、胜负条件和节奏。
- 明确 Solar、Home、Battery、EV、Grid 的职责与能量流向。
- 定义 Money、Family、Score 的来源、消耗与反馈。
- 设计随机事件、Roguelike 三选一升级和 Boss 的初版规则。

### 完成目标

不写代码也能从 00:00 推演到 Game Over；知道玩家每秒看什么、做什么，以及为什么会输。

## 阶段 2：核心原型

### 工作内容

- 实现最小 Game Loop 和固定时间 Tick。
- 实现 Solar → Home → Battery → EV/Grid 的基础能源结算。
- 实现资源变化、基础按钮、事件提示和 Game Over。

### 完成目标

在一个简单 Game Screen 上完整玩完 3 局，暂不追求漂亮视觉。

## 阶段 3：游戏性验证

### 工作内容

- 反复试玩并调整能源产消、价格、事件频率、升级间隔和难度曲线。
- 验证玩家是否理解失败原因，是否愿意立即重开。
- 找出无聊点、过强升级、无意义操作和突兀难度。

### 完成目标

核心循环开始产生紧张感和策略差异；一局时长稳定在目标范围内。

## 阶段 4：内容扩充

### 工作内容

- 扩充升级池、事件库和 Boss 类型。
- 增加有明显取舍的 Build 路线。
- 增加基础成就或局内挑战。

### 完成目标

不同对局出现可感知的差异，玩家愿意尝试新的组合。

## 阶段 5：视觉与手感

### 工作内容

- 优化能源流动、警告、按钮、升级选择和失败反馈。
- 加入必要的动画、音效和触觉反馈。
- 调整手机屏幕上的信息层级与可读性。

### 完成目标

从功能 Demo 变成具有明确反馈、节奏和主题感的小游戏。

## 阶段 6：长期玩法

### 工作内容

- 增加解锁、每日挑战、难度变体或局外成长。
- 评估排行榜、分享和统计功能是否真正服务于留存。

### 完成目标

玩家有理由在完成一局后继续尝试，也有长期目标可追踪。

## 阶段 7：发布

### 工作内容

- 完成设备适配、性能检查、存档与异常处理。
- 准备商店介绍、截图、图标和隐私相关材料。
- 进行完整回归测试和小范围试玩。

### 完成目标

形成可稳定安装、游玩和发布的独立小游戏版本。
